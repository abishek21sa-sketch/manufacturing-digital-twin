# Data and Evidence Boundary

The included `data/external/orlib/jobshop1.txt` is a public OR-Library job-shop benchmark source. The repository defaults to the Fisher–Thompson `ft06` instance. OR-Library describes `jobshop1` as containing 82 test instances commonly cited in the literature.

Source page: `https://people.brunel.ac.uk/~mastjjb/jeb/orlib/jobshopinfo.html`
Source file: `https://people.brunel.ac.uk/~mastjjb/jeb/orlib/files/jobshop1.txt`

The benchmark supplies routing and deterministic processing-time data. It does **not** supply live plant telemetry, actual due dates, breakdown history, quality history, workers, material availability, or realized business outcomes. V1.0 therefore labels its factory definition `public_benchmark` and does not fabricate those missing fields.

## Public sources checked and demo data

There is no single public source that provides the complete combination of
event-sourced shop-floor state, finite-capacity scheduling, machine reliability,
quality, and policy outcomes required by this portfolio application. Public
sources are therefore used by method, not presented as a complete plant twin:

| Source | What it contributes | Boundary |
|---|---|---|
| [UCI AI4I 2020](https://archive.ics.uci.edu/dataset/601/ai4i) | 10,000-row predictive-maintenance reference | It is itself synthetic and is not an event-sourced scheduling history; CC BY 4.0. |
| [UCI SECOM](https://archive.ics.uci.edu/dataset/179/secom) | Semiconductor process sensor/yield reference | 1,567 examples, 591 features; not a twin event ledger; CC BY 4.0. |
| [NASA PCoE repository](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/) | Reliability/prognostics and run-to-failure references | Source-specific terms must be checked before redistribution. |
| [OR-Library job shop](https://people.brunel.ac.uk/~mastjjb/jeb/orlib/jobshopinfo.html) | Public scheduling instances, including the FT06 baseline | Optimization benchmark only; check the OR-Library legal notice before redistribution. |

For a safe, self-contained website and career-fair demo, the repository also
ships `data/synthetic/mdt_operational_scenarios_150000.csv`. It is generated by
`scripts/generate_synthetic_dataset.py`, contains 150,000 reproducible rows
and 80 governed columns
covering ten scenario families, and is explicitly labeled
`source_kind=synthetic_demo`. Its manifest records the seed, schema version,
coverage, public references, and SHA-256 digest. It is a scenario-observation
dataset for analytics and demonstrations; it must not be described as real
plant telemetry or as a realized business result.

The workbench integrates the dataset through a read-only summary endpoint at
`GET /v1/data/synthetic` and a controlled download endpoint at
`GET /v1/data/synthetic/download`. The summary refuses to report `READY` unless
the row count, column count, and SHA-256 digest match the manifest. The dataset
is intentionally not passed to the canonical event replay endpoint because its
rows are balanced scenario observations rather than one chronological event
history for the FT06 benchmark.

Future external data follows:

`source -> adapter -> canonical FactoryModel/ManufacturingEvent -> validation -> event ledger -> twin state`
